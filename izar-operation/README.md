# Izar operation

`GraphQlRequest` describes a generated GraphQL request with its executable document, derived operation ID, and variables. `GraphQlOperation<TResponse>` extends that contract with Izar's `decode` method. The module has no dependency on Spring, Reactor, or GraphQL Java, so generated request and response types expose none of those frameworks to their caller.

## Add the dependency

```xml
<dependency>
    <groupId>dev.glisseo.izar</groupId>
    <artifactId>izar-operation</artifactId>
    <version>0.1.0-SNAPSHOT</version>
</dependency>
```

Most applications never add this directly. It arrives transitively through code generated by [izar-maven-plugin](../izar-maven-plugin/) and through [izar-client](../izar-client/), which executes Izar operations against a Spring GraphQL client. Add it by hand when a project reads generated request metadata or decodes generated Izar operations without depending on izar-client, or when it declares a custom scalar codec (see below) in a module that does not already carry the dependency transitively.

## The operation contract

`GraphQlRequest` is the base contract for generated request metadata:

```java
public interface GraphQlRequest {
    default GraphQlOperationKind operationKind() { return GraphQlOperationKind.QUERY; }
    String operationName();
    String document();
    String operationId();
    Map<String, Object> variables();
}
```

`GraphQlOperation<TResponse>` adds response decoding:

```java
public interface GraphQlOperation<TResponse> extends GraphQlRequest {
    TResponse decode(@Nullable Object data, DecodingPolicy policy);
    default TResponse decode(@Nullable Object data) {
        return decode(data, DecodingPolicy.LENIENT);
    }
}
```

Generated operations set `operationKind()` to the operation declared in the `.graphql` file. The compiler generates `Query`, `Mutation`, or `Subscription` class suffixes to match that kind.

Generated `JACKSON` operations implement `GraphQlRequest` and use Spring GraphQL's JSON mapper to create their response records. Generated `IZAR` operations implement `GraphQlOperation` and include `decode`. `document()` returns the exact executable document text sent on the wire. `operationId()` is the lowercase hex SHA-256 digest of that document, computed at build time so a client never has to hash the document itself and risk disagreeing with a manifest entry. `variables()` returns the encoded map for a variable-bearing operation or an empty map when the operation declares no variables. `decode` takes the raw `data` value of a GraphQL response, a nested structure of `Map<String, Object>`, `List`, JSON scalars, and `null`, and converts it into the operation's response type.

`DecodingPolicy` controls what `decode` does when it meets an enum value or a polymorphic (interface or union) concrete type that the schema did not know about at generation time. `LENIENT`, the default used by the no-argument `decode` overload, preserves the unfamiliar value in a generated `Unrecognized` representation. `STRICT` fails decoding instead, with a message naming the enum or type and the unrecognized value. The policy is passed as an argument rather than fixed at generation time, so one caller can choose `STRICT` at construction and apply it consistently without affecting any other code executing the same generated operation.

Generated input builders call `GraphQlEncoding` for list and custom scalar conversion. `GraphQlDecoding` supplies the scalar, enum, and list conversion that generated `IZAR` decode methods call. Application code does not normally call these helpers directly.

## Writing a custom scalar codec

`ScalarCodec<T>` is the extension point for a custom GraphQL scalar that generated code needs to encode and decode:

```java
public interface ScalarCodec<T> {
    T decode(Object raw);
    Object encode(T value);
}
```

Generated code constructs one codec instance per distinct scalar through its public no-argument constructor, and never passes `null` to `decode` or `encode`: a missing value is handled before the codec is invoked. `decode` receives the raw value already extracted from a parsed response (a `String`, `Number`, `Boolean`, `List`, or `Map`, depending on how the scalar is represented on the wire) and must throw if it isn't a valid representation; `GraphQlDecoding.decodeScalar` and `GraphQlEncoding.encodeScalar` catch that exception and wrap it with the scalar's name for a clearer message. `T` must be immutable, or `decode`/`encode` must defensively copy it, since a generated response record is supposed to stay immutable regardless of what a caller does with the value afterward.

A minimal codec for a `UUID` scalar:

```java
public final class UuidScalarCodec implements ScalarCodec<UUID> {
    @Override
    public UUID decode(Object raw) {
        return UUID.fromString((String) raw);
    }

    @Override
    public Object encode(UUID value) {
        return value.toString();
    }
}
```

For common scalars, [izar-scalars](../izar-scalars/) provides pre-built codecs for `java.time` types, `BigDecimal`, and similar, so most applications reach for it instead of writing a codec by hand. Write one directly only for a scalar izar-scalars does not already cover.

## What this module does not do

Izar operation depends on nothing beyond the shared parent POM. Adding any dependency here would attach it to every generated operation in every consuming application, so this module stays deliberately empty rather than accumulate a convenience each generated operation would carry regardless of whether it is used. In particular, it does not:

- Execute a GraphQL request over HTTP. [izar-client](../izar-client/) does that.
- Ship any pre-built scalar codec. [izar-scalars](../izar-scalars/) does that.
- Generate Java classes from a schema and operation files. [izar-compiler](../izar-compiler/) does that.
- Depend on Spring GraphQL or Jackson. `GraphQlRequest` contains request metadata only.
